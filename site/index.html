Message projects like teammates

Give work to a project the way you would to a colleague, from your Mac or your iPhone. The project agent takes it from start to finish, keeps the context on how you work, and comes back when it needs your approval.

Work with many projects at once

Create a project, give it a task, and add another when the work grows — one on the website, one on research, one on the books. They run in parallel on your machine, talk to each other when it helps, and keep working while your laptop is closed.

Your own cloud machine

Every user gets one cloud computer. It starts when you send a message and stops when you leave, so there is nothing to run and nothing to pay for while it sleeps.

Give each project a job

FAQs

How is Arbos different from a chat assistant?

A project in Arbos has its own computer. It can run code, use a browser, sign in to your tools, and keep working after you close the laptop. A chat assistant answers; a project finishes the work and comes back.

Do projects share one computer?

Yes. Every user gets one cloud machine. Each project is a separate workspace on it with its own directory, process group, memory, and history. Isolation is per user, so your projects can hand files and context to each other, and nobody else's can.

Who runs the machine?

We do. The machine starts when you send a message and sleeps when you go quiet. Inference, hosting, and app updates are managed for you. If you would rather run it yourself, the whole stack is open source.

Where do I talk to Arbos?

From the Mac app, and from the iPhone app in the TestFlight beta. Both show the same threads. Voice memos work on both; channels such as Slack and Telegram are on the roadmap.

Can projects talk to each other?

Yes. A project can message another project directly, and you can put several in one group chat. They pass work between themselves and you watch the thread instead of relaying messages.

What can a project connect to?

Connectors for Gmail, Google Calendar, Slack, and GitHub, used as you. Routines that run on a schedule or on an event. A skills library you can edit. A credential vault for logins and keys. Local access to your Mac, with a separate approval for every action.

How does Arbos handle my data?

Sign-in is GitHub OAuth. Tokens for your connectors stay in the relay and never enter the machine. Vault items are encrypted at rest and injected as placeholders, so the model sees ••••. Anything that leaves the machine goes through an approval card first. The code is public, so you can check all of this.
